## In simple words (for the owner)
Beacon, the app's new mascot, is drawn and now lives in your lessons. It's a thin lattice tower with a round glowing head that has a face, and soft radio rings around the head that slowly "breathe". It blinks every few seconds. When you answer, it changes face straight away: a smile and a green ring for a right answer, a worried look with a little drop for a wrong one. When you finish a lesson it hops and sends out rings. It has six faces (waiting, happy, oops, thinking, cheering, sleepy); the other two get used later (R18). The old triangle with the waving antenna is gone. "Reduce motion" keeps Beacon still.

## Notes for the next Claude
- **Using Beacon:** `import { Beacon, BEACON_SIZE } from './ui'`; `<Beacon face="happy" size={BEACON_SIZE.question} />`. `data-testid` defaults to `beacon`; `data-face` and `data-looping` are on the `<svg>`. Parts carry `data-part` (`tower`, `head`, `rings`, `pulse`, `burst`, `face-disc`, `face`, `eyes`, `drop`, `dots`, `z`) for tests.
- **Two loops:** Beacon uses both of a screen's allowed background loops (breathe and blink). On the path (R18) the current lesson already breathes, so use `still` there or follow idea I35.
- **One-off moves use the state change, not a remount:** pulse, hop and burst animate when `face` changes (the target changes), so they replay every time the face goes back to happy / cheering. If Beacon first appears already cheering, nothing hops (it uses `useEntrance`).
- **The "window hidden" test fakes `document.visibilityState`** (as `pathmotion.spec.ts` does): hiding the real Electron window under xvfb doesn't change it (tried in R17).
- **Reaction time test** measures click → `data-face` change inside the page. If it ever fails on Windows, look first at what runs inside the click (sound, confetti), not at Beacon: Beacon itself costs about 5 ms.
- Click tests need the pretend screen: `xvfb-run -a npm run e2e`.
