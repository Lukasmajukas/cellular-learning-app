## Notes for the next Claude
- **How the moments play:** `useChange(key, value)` in `TopBar.tsx` gives `{from, to, n}` (module memory `shown`, reset when the app restarts). `useMoment(ref, change, play, keys, transition)` runs Motion's `animate()` on the element once per change. Imperative `animate()` doesn't care that the screens' AnimatePresence skips first animations, so no `useEntrance` was needed there (the goal bar's fill uses `useEntrance` through ProgressBar's `from`). Imperative `animate()` ignores `MotionConfig`, so each moment checks `useCalm()` itself.
- Things that only show during a moment start invisible in their style (`opacity: 0` for the "+N" and the flash, `scale(0)` for the check) and are keyed by `n`, so a new change gets a fresh element.
- `TOP_BAR.flame` and `TOP_BAR.popScale` hold the numbers; the `...Keys` are built from them as transform strings.
- The count-up uses `useMotionValue` + `useTransform` rendered as a child of `<motion.span>`: never set `textContent` by hand (React would lose its text node).
- `TOP_BAR` isn't `as const`: Motion's `animate()` types want changeable keyframe arrays.
- Test ids: `streak`, `streak-flame`, `streak-glow`, `xp-total` (`data-to` = the final value), `xp-today`, `xp-float`, `freezes`, `goal`, `goal-bar`, `goal-flash`, `goal-check`, `goal-text`, `repair-card`, `repair`.
- **Windows build caught one thing (first two runs):** only frame rates failed, all just under 50: the top bar moment 49.3, coming on air 50.0 (54.7 in R06) and unit done 48.8 (50.3 in R06). Those two path tests also play the top bar moment now, so the top bar was adding work on top of the path's celebration. Measured in the cloud with the CPU slowed 6x (Chrome DevTools `Emulation.setCPUThrottlingRate`, a scratch test, not kept): coming on air 49.5 fps with the first top bar, 55.4 with its moments off. Made cheaper: every moving piece now animates a whole `transform` string plus opacity (the browser runs those on its graphics side; separate `scale`/`rotate`/`y`/`x` are run by Motion's JavaScript every frame), the counting number has a fixed width with `contain: layout paint`, today's XP no longer counts separately, and `ProgressBar`'s fill also animates `transform: translateX()`. Result at 6x slower: 53.6 fps. **Use this trick for anything new that moves during another moment, and the 6x-throttle test to compare before and after.**
- `film()` is in `tests/helpers.ts` now; each frame has `op`, `sx`, `sy`, `x`, `y`, `tx`.
- The sample lesson played by `playSampleLesson` earns 10 XP (it always picks the first answer).
